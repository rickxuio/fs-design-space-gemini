FS Design · Operation Manual

中保真设计稿合成操作手册

如何用 Kiro 配合 FS 设计知识库，把一句话需求或一个参考网址，转化为符合 FS 设计规范的中保真页面设计稿。

适用对象：设计师 / 产品 / 前端 · 无需手写代码 · 基于 fs-design-system.md 知识库

1. 这份手册是做什么的

Kiro 是一个 AI 开发环境。它能读取本项目里的「FS 设计知识库」，把你的自然语言需求转成一份遵守 FS 设计规范的 HTML 页面设计稿。你不需要写代码，只需要会描述需求、会检查结果。

输入

你提供什么

一句话页面需求，或一个参考网址 / 截图 / 文档。说明页面类型、要展示的内容模块和主要文案。

处理

Kiro 做什么

读取知识库规则 → 把内容映射成 FS 组件 → 用 ds-* 类生成 HTML → 自检并修正违规项。

输出

你得到什么

一份可在浏览器打开的中保真 HTML 页面，颜色、字体、间距、组件结构都符合 FS 规范，可直接评审或交付前端。

中保真的含义：结构、布局、组件、规范色彩和间距都到位（可点击、可滚动），但图片用真实或占位图、文案为示例级，不含真实业务数据和最终视觉精修。

2. Kiro 的生成流程（四步法）

这是 Kiro 内部每次都会执行的强制流程。理解它能让你知道每一步该看什么、该确认什么。

1
读规范
先读 fs-design-system.md、tokens.css、components.css，以及页面会用到的每个组件 preview/*.html。绝不凭记忆写组件。
2
声明确认 + 组件映射
列出页面需要哪些组件、确认关键数值（版心 1200px、section 间距 40px、品牌红 #C00000 等）；重构页面时把源页面每个模块映射到 FS 组件。
3
写代码
只用 ds-* 类，从对应 preview 文件复制结构、替换文案；按白↔灰交替排布 section；header/footer 直接复用 FS 片段。
4
自检修正
对照自检清单逐项检查（颜色、卡片边框、按钮、字重、版心、间距…），发现违规立即修正后再交付。
你能看到全过程：Kiro 会在对话里展示它读了哪些文件、做了哪些映射和修改。你可以随时打断、追加要求或让它回退。

3. 如何向 Kiro 提需求

需求越具体，结果越准。根据你手上有什么素材，选择对应的指令模板直接套用：有竞品网址用「基于竞品」，有原型图用「基于原型」，有需求文档用「基于需求文档」。

模板 A · 基于竞品

【页面链接 + 截图】改版这个网页，要求：
1、100% 复刻原网页的文字和功能；
2、完全按照 FS 的规范来重构视觉；
3、保存到 pages/【页面名称】.html，并在 index.html 添加入口卡片。

模板 B · 基于原型

【原型图】基于此原型图生成页面，要求：
1、100% 复刻原型图的文字和功能，逐个板块对照原型截图确认，不遗漏任何文字和结构；
2、完全按照 FS 的规范来重构视觉；
3、保存到 pages/【页面名称】.html，并在 index.html 添加入口卡片。

模板 C · 基于需求文档

【上传 Markdown 文件】请根据提供的页面内容文件，严格遵循以下要求生成网页：
1、100% 完整保留所有文字内容，确保信息准确无误，不进行任何删减或修改；
2、完全按照 FS 的规范来重构视觉；
3、内容均使用英文；
4、保存到 pages/【页面名称】.html，并在 index.html 添加入口卡片。

模板 D · 局部修改已生成页面

把第二个 section 改成灰色背景，卡片改成 3 列；
其他模块不要动。
提需求时避免：指定非系统色（黄/绿/青背景）、自定义字重、要求红色用在 banner 或普通卡片上 —— 这些会被规范过滤，Kiro 会替换为合规方案并告诉你原因。

让结果更可控的小技巧

想要的效果怎么说
明确页面层级说清楚是「落地页 / 解决方案页 / 知识库页 / 专题页」，决定用哪种横幅变体。
控制卡片排布说明「几列网格」「图左文右还是图上文下」。
指定真实配图直接给图片 URL；不给则会用主题相关占位图并标注，方便你替换。
限定修改范围明确「只改 X，其他不动」，避免顺手改到别的模块。

4. 两种典型任务

实际使用中，需求基本落在这两类。它们走同一套四步流程，区别在于「重构」多了一步源页面品牌过滤。

全新页面
  • 你描述模块和文案，Kiro 从 FS 组件搭建
  • 配图默认用主题相关占位图（验证可访问）
  • 适合：新落地页、专题页、活动页
  • 关键：说清楚页面类型和模块顺序
重构参考网页
  • 提供网址 / 截图，Kiro 提取内容与结构
  • 保留内容与功能意图，丢弃源站品牌外壳
  • 源站 header/hero/footer 一律换成 FS 版本
  • 关键：确认配图 URL 和面包屑文案完整

5. 拿到稿子后怎么检查

Kiro 会自检，但交付前你也应快速过一遍。下面是最容易出问题、也最值得你确认的几项。

检查项合规标准
背景色只允许 #FFFFFF / #FAFBFB / #19191A / #4B4B4D，无黄/绿/青/紫等非系统色。
红色用法红色只出现在表单提交按钮、Hero 搜索按钮；banner、卡片、普通内容区不能用红。
卡片边框白色 section → 四边边框；灰色 section → 无边框白卡；横向卡片不加边框、hover 无投影。
版心与间距内容版心 1200px 无水平 padding；section 上下 40px；卡片间距 20px，最多 4 列。
section 交替白↔灰严格交替，不能连续两个同色。
字体字重Open Sans，仅 400 / 600 两种字重。
header / footer用 FS 标准片段，footer 链接、badge、legal 条目完整未删减。
配图真实可访问的图片 URL（HTTP 200），不是纯色占位块；占位图应被标注。
不满意可以继续对话：直接说「这里改成…」「这个模块去掉」，Kiro 会在原稿上增量修改，无需从头重来。

6. 常见问题

我完全不懂代码，能用吗？

能。你只需要描述需求、看浏览器里的页面效果、用自然语言提出修改意见。代码由 Kiro 编写和维护。

生成的页面在哪里看？

Kiro 会把 HTML 文件保存到项目里（全新页面源文件在 page-sources/，重构测试页在 pages/）。双击用浏览器打开即可。

为什么我要的某个颜色 / 样式被改掉了？

因为它违反 FS 规范。规范优先级高于参考来源，Kiro 会替换成最接近的合规方案，并在对话里说明替换原因。

重构网页时图片拉不到怎么办？

遇到反爬无法获取源图时，Kiro 会告知你并请你提供图片 URL，或先用主题相关占位图并标注，方便你后续替换为正式素材。

规范更新了，页面会自动跟着变吗？

已生成的静态页面不会自动变。规范更新后，让 Kiro 基于最新知识库重新生成或检查页面即可。

这份稿子能直接上线吗？

它是中保真设计稿，用于评审和交付前端。上线前仍需替换真实数据、正式素材，并由前端做生产级实现与适配。占位图属示意，正式商用图片需确认授权。
