本地页面布局规范

这里说明页面布局、来源处理和验收。组件的样式、变体、状态和依赖以当前组件库为准。

项目首页 · 组件库与变体决策 · 完整页面规则 · 操作帮助

页面布局

项目原有规则
版心最大1200px、居中，容器无水平padding
区块上下各40px，白色#FFFFFF与浅灰#FAFBFB交替
网格gap20px，最多4列，可使用1—3列
区块标题24px、600、32px行高，居中
内容间距标题到描述12px；描述到内容24px
描述14px、400、22px行高，居中，最大960px，#707070
页面字体Open Sans，400/600；组件内部遵从实际契约

组件从哪里读取

从当前selection和catalog选具体可调用变体，核对契约、真实Preview、允许字段、子组件及资源。使用library-*调用，固定同版本Header/Footer和资源；不读已退役的旧组件目录、不改锁定结构、不混载CSS。

来源与配图

  • 忠实保留来源正文、顺序、链接和功能意图；原站头尾、Logo和品牌视觉过滤为FS规范。
  • 配图位用真实图片，核对主体及裁切；图标用当前登记资源并确认语义。具名头像不套陌生人脸。
  • 白字叠背景图用原组件提供的纯色半透明深色遮罩，不用渐变或页面样式覆盖。
  • 组件缺口先查契约和Preview，不用原站iframe、未登记表单或自绘组合绕过。

原工作流与验收

读取规范 → 确认组件 → 来源品牌过滤 → 模块映射 → 编写页面 → 自动检查 → 实际渲染核对。

普通页面保存到pages，原页面级规范管线保留。使用npm run check -- pages/目标页.html，自动检查后逐模块看图，核对选型、文案、图标、图片与动作。已有回归输入只用于工程验证，不作为新页面模板。

组件维护

在原design-system来源协调HTML、契约和共享实现，沿component:sync/watch更新父组件、调用、选型、依赖及展示；已交付页固定原版本。不额外增加页面流程、阶段或报告。
