# FS 组件规范质量标准 v1.0

目标：更新规范时不丢关联、不沿用过期结论；合成页面时选对变体、调用真实组件、保留允许的内容与交互。

本标准由 Agent 负责工程质量、检查与差异说明。设计来源决定视觉事实；用户视觉批准单独记录。不会因文档齐全、旧 isComplete=true 或一项测试通过就宣布整个组件家族合格。

## 每个组件必须回答的八个问题

| 问题 | 合格要求 | 不合格时怎么处理 |
| --- | --- | --- |
| 从哪里来 | 原始组件与规范解读分开；节点、版本、读取范围、差异与本地快照可追溯 | 标记仅本地实现；不宣称同步 MasterGo 最新版 |
| 什么时候用 | 每个已开放变体有用途、排除场景；尺寸/状态/宿主限制明确 | 不凭名称或视觉相似度强行选型 |
| 怎么调用 | 唯一真实实例、完整根节点/类名、必需结构及 CSS/JS；多尺寸提供各自真实示例 | 结构缺失或不唯一则阻断，不重新编写内部实现 |
| 什么能改 | 每个字段对应唯一槽位及 text/structured-content 修改方式；业务回调声明 event-handler，必要原生属性使用枚举 native-attribute；其他默认锁定 | 字段无槽位或类型绑定则阻断；不把示例业务内容误当必需规则 |
| 跟谁联动 | 子组件的变体、尺寸、槽位和实现证据一致；父关系反向生成；图标与 Token 指向源头 | 缺依赖、父子禁止规则冲突、只套类名均不合格 |
| 改了会怎样 | 修改记录包含原因、来源、兼容性、受影响父子组件；源变更使旧验收失效 | 先报告影响，完成同步与对应检查后才发布 |
| 怎么证明 | 结构/负例/计算样式/交互/独立装配均有证据；验收绑定源文件及检查工具指纹 | 字段写 verified 不算证据；过期证明不得继续用 |
| 页面是否稳定 | 新页面锁定本地组件运行版本，历史页人工请求才升级 | 锁定资源损坏则阻断；不回退到最新共享文件 |

八项不能用平均分抵消。颜色、字号、尺寸、圆角、间距按来源和 Token 检查，不由 AI 随意美化。

## 新 Icon 的本地保存与联动

### 原子与嵌套关联（2026-10-10 用户确认）

组合组件以原子组件为主。嵌套必须真实调用已确认的原子变体、DOM、图标与运行资源，并登记宿主槽位及反向父关系；宿主只负责装配位置和业务事件，不复制或覆盖原子的尺寸、圆角、颜色和状态样式。设计宿主中的旧覆盖与文字规范不一致时保留来源差异，不再把三者作为平行方案默认混用。原子修改须使关联宿主的旧验证失效并同步复核；已冻结历史页面仍保留锁定版本，明确升级才改变。

新组件涉及新的 Icon 时，先核对 Icon 规范及现有本地 SVG；已有匹配资源复用，新增资源从真实设计来源取得并保存到 `components/icons/`。记录来源与宿主组件、变体、状态、SVG 文件的准确对应关系，并核对角色、尺寸、颜色、线条、位置和间距。无法取得、导出或保存可靠资源时，说明缺失并询问用户，不猜测、不用相似图标、字符或自绘 SVG 替代，不将该组件标为完成。Icon 规范或 SVG 更新后须追踪受影响的父子组件，并让相关旧验证失效。

## 合格的状态分开记录

- **维护登记完成**：有统一来源入口、选型规则指针、同步路径和变更要求；表示纳入治理，不代表视觉或 AI 调用已验收。
- **精确结构检查通过**：真实实例、槽位、尺寸和依赖可机器读取；仍需计算样式、交互和更新回归。
- **工程参考合格**：本次声明范围的检查通过，验收记录与当前源和工具指纹匹配；视觉审阅可以待确认。
- **视觉批准**：用户明确批准对应变体；工程状态不能代替它。
- **完整家族合格**：所有声明形态均覆盖；部分模板通过不等于整个家族通过。

`components/quality/report.json` / `.md` 为自动盘点；`components/quality/acceptance.json` 保存工程验收证据。来源、工程、视觉与家族覆盖是四个独立状态。

## 现有工程检查入口

在项目根目录按实际变更范围使用原命令：

| 命令 | 用途 |
| --- | --- |
| `npm test` | 本地装配、字段约束及限制回归 |
| `npm run test:sync` | 隔离副本中的真实父子同步与版本保护 |
| `npm run design:check` | 组件源、契约及派生资料一致性 |

这些检查用于组件或工具维护，不加入每次页面合成。普通页面沿原 `npm run check -- pages/目标页面.html` 并实际看图。工程验收仍需匹配实际源及工具指纹；结构检查不替代浏览器、来源或视觉证据。

## 原始组件与规范正文冲突（2026-10-12 用户确认）

- 用户明确：“所有的都以组件为准”“规范正文都是出自于组件，如果有矛盾，一般都是规范正文不对”。此原则适用于本项目全部组件：规范正文由原始组件整理而来，二者冲突时以有效MasterGo文件中已核实的对应原始组件、具体变体与状态为准，记录并修正正文解释，不重复要求用户逐项选择。
- 不以本地旧实现替代原始组件；真实节点、引用、尺寸和状态证据不足时仍标为待核对。例图标注与实际节点测量分开记录，不将标注冒称实测。
- 原子与宿主仍遵守原子优先；源头与正文的冲突记录保留，冻结历史页面不自动升级，不因此收集新组件或恢复暂缓适配。

## 维护与发布

维护步骤和父子影响处理见[组件维护](component-contribution-guide.md)。页面执行顺序以项目根目录[AGENTS.md](../../AGENTS.md)为准；本标准只定义质量与证据边界。

结构、槽位语义、尺寸名、事件或依赖移除/重命名属于可能不兼容变更，必须重新检查受影响调用；不能仅更新版本号。Token 名称与 styleProperties 的缓存色号不一致时也阻断同步：先确认 Token 声明与 CSS 一致，再修正过期标注；不改 Token 名称或 CSS 来掩盖旧标注。微调文案也必须重新确认槽位和溢出，不能凭“只是文字”跳过。

## 组合组件与当前调用范围

Dialog等组合组件按具体变体核对来源、真实子组件、布局、焦点和交互。工程范围读取当前catalog、契约和验收记录，不沿用早期试点模板数量；一个实例通过不代表完整家族通过。

组件族已接入、某个变体可调用、来源核对和视觉批准分别判断。缺少原件或精确槽位时保留缺口，不猜DOM、图标或事件；尚未开放的变体不因相似而调用。

组件维护沿根目录AGENTS的现有要求按依赖检查影响，复用仍有效的证据。MasterGo在线变化需要重新读取；本地同步不代表在线读取或视觉确认。

## 本地预览与使用状态

- **组件预览展示边界（2026-10-12 用户确认）**：组件展示区只能展示有效MasterGo组件库中有对应来源的真实组件、变体和状态，不添加AI自行组合的能力演示。纯文字、任意图标左右位置、宿主折叠适配等未取得对应原件的演示，不混入原始组件展示；已有真实宿主适配在对应宿主中记录，不冒称原子新增变体。


正式组件预览读取同步生成的来源修订标识，源头或验收状态变化后刷新；标题下显示当前工程/视觉状态。仅本地 HTTP 服务生效，文件浏览保持静态。历史页面不加载这个辅助脚本。自动刷新不等于在线读取 MasterGo，也不代表待复核项已自动通过。
