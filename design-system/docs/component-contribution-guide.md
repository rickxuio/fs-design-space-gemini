# 组件维护

本页说明现有组件维护机制。页面合成继续使用项目根目录的 `AGENTS.md` 和[本地页面布局规范](../../design-spec/fs-design-system-preview.html)，不使用独立的投喂或页面登记流程。

[组件库与变体决策](../component-library.html#library) · [项目说明与源目录](../../README.md) · [本地页面布局](../../design-spec/fs-design-system-preview.html)

<h2 id="maintenance">维护已有组件</h2>

从组件库打开目标组件，核对原契约、真实 Preview、MG 原件及已读取范围。设计来源、工程验证和视觉批准分别记录，文件存在或旧状态不能代替当前调用资格。

HTML 的设计差异由维护者理解，再协调契约、共享 CSS/JS、图标与父子依赖。派生目录不直接修改；已交付页面保持其原固定版本。

组件目录只维护规范、契约、真实Preview、变体映射和运行资源；页面执行要求仍读根目录AGENTS。保留被引用的MG原件、核对证据和真实工程日志，不恢复独立页面登记或阶段流程。

<h2 id="decisions">步骤2：核对变体决策和父子依赖</h2>

沿用当前 Button 样板的“变体／匹配条件／选型结论”，每条决策应能指向具体变体，并说明排除场景、尺寸、状态及设备限制。

| 核对项 | 要求 |
| --- | --- |
| AI 选型 | 当前 catalog 允许调用；决策与契约、Preview、真实用途一致 |
| 可编辑内容 | 明确 slots、bindings、allowedEdits 和禁止改动的结构 |
| 子组件 | 指向真实组件与具体变体，保留必需图标和状态 |
| 父组件 | 核对反向引用，判断变化是否需要同步父组件实例 |
| 运行资源 | 保持 CSS、JS、字体、图标及固定版本完整，不混版 |
| 来源 | 保留 MG 原件、节点身份、核对范围及已知差异 |

确认新增组件前先搜索现有契约、变体决策和 Preview；已有组合不重新建立。确有缺口时明确说明，不用原站整块 HTML、未登记控件或静态替代隐藏缺口。

<h2 id="commands">使用原维护命令</h2>

在项目根目录执行，组件名按实际目标替换：

```bash
npm run impact -- button
npm run component:check
npm run component:sync
```

`impact` 查看父子关系；`component:check` 只读检查现有导出。发现过期先核对实际差异；`component:sync` 是发布操作，沿现有机制更新依赖、选型、调用片段及规范展示。多文件调整在隔离副本验证稳定后，正式项目发布一次；已有页面不自动升级。

仅调整公共规范展示模板时使用原 `npm run docs:build`。展示更新不等于开放变体。

<h2 id="verification">工程与视觉核对</h2>

修改组件或验收工具时，按影响范围运行现有有限工程测试；验收过期后实际复验，保留结果与源、工具指纹。普通页面继续使用根目录的 `npm run check -- pages/目标页面.html`，并实际看图核对内容、图标语义和交互。

[组件质量标准](component-quality-standard.md) · [当前工程报告](../components/quality/report.html) · [当前可调用目录](../../fs-components/component-specs/library/catalog.json)

工程通过、MG 来源核对、视觉批准和完整家族覆盖分别判断。当前状态读取实际索引，不沿用历史试点数量；脚本通过不代表视觉批准或业务请求已接入。

<h2 id="ownership">发现问题时修改哪里</h2>

| 问题 | 修改位置 |
| --- | --- |
| 页面传参或内容归属错误 | 页面装配 |
| 选错变体 | 按现有决策更换具体变体 |
| 契约、Preview 或共享实现有误 | 组件维护源，随后沿原同步机制处理 |
| 来源不足或能力未开放 | 记录实际缺口，核对原件，不伪造可调用状态 |

保留现有本地工作流、父子依赖和同步机制，不增加确认关卡、阶段报告或第二套页面流程。
