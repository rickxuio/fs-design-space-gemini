变体决策

先匹配具体场景，再区分候选、不用与设计参考；展示和AI读取同一规则。MG来源事实、当前本地接口和视觉批准分别记录，不扩展既有调用范围。

变体匹配条件选型结论
Hero（首页级）1920首页单图，标题/描述/单CTA完整。候选 · hero；1920单图，已有白色描边XL按钮，深色背景由宿主提供。
需要搜索，或只有标题。不用 · 按Search/Title-only判断，不默认Hero。
Sub（解决方案页）1920×320解决方案，保留深色路径。候选 · sub；保留当前必需的完整深色面包屑。
仅因有面包屑就选择Sub。不用 · 先看用途和内容，面包屑不是选型条件。
需要无路径、播放或Pad/M。设计参考 · 无面包屑、播放及适配仍未开放。
Search（知识库）知识库或案例页的关键词搜索顶部，42px真实搜索输入与FS GPT宿主入口。候选 · 使用search并由宿主接搜索或GPT意图；不伪造搜索结果与AI回复。
普通产品选择、自动搜索结果、已接入AI回答或手机布局。undefined · 按实际内容另选，不用关键词搜索伪装配置选择。
Title-only（专题页）桌面200px，仅完整标题。候选 · title-only；完整标题，不删来源描述或按钮。
来源有描述或CTA。不用 · 重新选型，不能删内容适配组件。
Mini（商品详情页）PC商品详情内容中的120px窄幅信息，需真实三项分页切换。候选 · 三项内容与同版Carousel分页联动，文字链接仍用TextButton。
首页Hero、自动播放大图或未核对的M/Pad形态。不用 · 不扩大为其他场景或后台业务。
响应式 Hero（完整文案）多窗口信息页，标题/描述/单CTA完整。候选 · hero-responsive；已有本地完整文案适配；图片/遮罩由宿主维护。
仅为适配而编造描述或CTA。不用 · 不编造描述或CTA，按来源重新选型。
⚠️ 硬规则：桌面Hero采用原组件404px内容内缩
描述原文
1920×420桌面Hero沿原组件404px内容内缩，单个白色描边42px Button。页面不得覆盖组件display或padding；图片在同一模块的页面级外层装配。
AI 解析（写入契约 JSON 的字段）
hero -> native1920x420; inset404; single outline-white/xl; background via pageLevelContent
⚠️ 硬规则：Banner 仅允许位于公共导航后的前一到两个内容模块
描述原文
Banner 的位置只能是固定 Header / 公共导航之后的第 1 或第 2 个内容模块；第 3 个及之后的模块、Footer 之前的其他深层内容，以及公共导航之前，均禁止使用 Banner。
AI 解析（写入契约 JSON 的字段）
section.positionAfterPublicHeader
  = 1 || 2

section.positionAfterPublicHeader >= 3
  -> Banner 禁止

positionBeforePublicHeader || positionInsideFooter
  -> Banner 禁止
⚠️ 硬规则：白字压背景图必须加深色遮罩
描述原文
白色文字叠在背景图上（Hero/Sub/Search/Title-only）时，图片必须加纯色半透明深色遮罩（box-shadow: inset 0 0 0 2000px rgba(0,0,0,0.5)），禁止用 gradient。
AI 解析（写入契约 JSON 的字段）
relations.enforcementStatus
  .darkTextOverlayRequiresScrim
  = { enforced: true,
      mechanism: "validate.js: checkImageOverlay (IMG_OVERLAY)" }
⚠️ 硬规则：Banner CTA 主次层级
描述原文
深色 Banner 只有一个 CTA 时用 outline-white；有两个 CTA 时，主操作用 filled-gray，次操作用 outline-white。禁止 filled-red；唯一例外是 Search 变体的搜索提交按钮。
AI 解析（写入契约 JSON 的字段）
relations.componentDependencies[0]
  .requiredVariants = ["filled-gray", "outline-white"]

variants[2].searchBoxSpec
  .submitButtonColor = "red
    （唯一允许的 filled-red 场景）"
