变体匹配条件选型结论
①居中型（方案）四步方案，当前/完成/待处理状态明确。候选 · 原PC初始四步；待开始禁点，不推断业务进度。
任意选择待开始步骤或自动进入下一步。不用 · 无阶段值/业务推进API，不模拟表单向导。
需要箭头、点状、竖向或Error步骤。设计参考 · MG另有原件，当前四个调用不覆盖。
②居中型（订单）订单状态、日期与顶部状态带。候选 · circle-centered-order；只读，标题无交互。
需要点击推进或可编辑订单阶段。不用 · 不是业务状态机，不新增路由/提交。
①常规型政策/服务有明确四阶段顺序。候选 · icon-regular；保留现有图标和连接箭头。
并列特性或普通图标卡片网格。不用 · 核对IconCard，不给内容伪造顺序。
MG建议最多5项或有其他图标原件。设计参考 · 当前固定4项，不按建议上限擅自增项。
②分隔线型About类四阶段，分隔线与圆形箭头。候选 · icon-divider；静态展示，保留原子图标。
标题箭头需要实际跳转或改变业务进度。不用 · 当前无跳转/推进接口，不把箭头当能力。
⚠️ 硬规则：圆标居中方案型状态与标题范围
描述原文
circle-centered-solution 仅允许 pending、current、completed。current 为绿色实心编号；completed 为浅绿底、绿色描边和本地 SVG 对勾；pending 为白底灰描边编号。不得输出异常/红色状态。标题短于可用范围时必须保持单行；只有超过“节点宽度 + 左右各半段连接线”的上限时才自动换行。
AI 解析（写入契约 JSON 的字段）
states = [pending, current, completed]
interactive currentIndex → 前序 completed / 当前 current / 后序 pending
title.maxWidth = calc(200% - 32px) // 左右各半段连接线
⚠️ 硬规则：圆标订单型状态带与交互
描述原文
订单型保留既有视觉状态，不提供点击或键盘切换。
AI 解析（写入契约 JSON 的字段）
order.interactive=false
⚠️ 硬规则：圆标居中方案型可用阶段切换
描述原文
当前 solution-completed-only 原子阻止未开始阶段的点击与键盘激活，仅可用阶段参与本地切换；不编造业务推进、校验或事件。URL保持不变。
AI 解析（写入契约 JSON 的字段）
interaction.circle-centered-solution = { urlChanges: false, keyboard: true }
⚠️ 硬规则：分隔线型标题调用当前TextButton原子
描述原文
当前icon-divider标题真实调用TextButton黑色14px加粗原子，使用其官方icon-text-button-arrow-right-bold.svg，尺寸12×12、Gray1，保持原子DOM和current资源。分隔线圆形图标继续按自身来源调用icon-stepper-divider-next.svg，24×24、Gray4圆底和白色箭头。宿主只装配位置，不覆盖TextButton的路径、颜色或状态；历史锁定资源保留原版本。
AI 解析（写入契约 JSON 的字段）
title = genuine TextButton inline-black-bold/l, official atom arrow; divider = existing icon-stepper-divider-next; host paint overrides forbidden; frozen resources unchanged
