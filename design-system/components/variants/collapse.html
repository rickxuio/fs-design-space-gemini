⚠️ 硬规则：展开模式：默认单开，split 可显式多开
描述原文
默认 single，同组展开一项时其余收起；仅 split 可显式配置 data-collapse-mode="multiple"，且须有来源证据和 Plan 登记。其他变体不开放多开。编号是标题内容，不能替代加减号状态指示器。
AI 解析（写入契约 JSON 的字段）
relations.enforcementStatus
  ["accordionRule.single-open"]
  = { enforced: true,
      mechanism: "components/collapse.js（事件委托：feature 鼠标悬浮展开、键盘激活切换；默认展开一项时收起同组其它项；仅 split 显式 multiple 时保留其它展开项；并处理 +/− 图标切换、ds-toggle 独立切换、行内编辑 Edit/Cancel/Save、数据预览行展开）" }
⚠️ 硬规则：基础分割型 header 使用语义按钮
描述原文
ds-collapse--split 的可交互 header 必须使用 button.ds-collapse__header，同步 aria-expanded 与 aria-controls；组件 CSS 统一清除原生按钮边框和背景。
AI 解析（写入契约 JSON 的字段）
relations.splitTriggerRequirement = "button.ds-collapse__header + aria-expanded + aria-controls"
⚠️ 硬规则：基础分割型核心结构必需，业务状态槽可选
描述原文
split 必须保留 root/item、button header、title 内加减号和 body，aria-controls 指向当前 body 的唯一 id。右侧 always/aside 为可选业务槽；来源没有时不渲染、不留占位。正文和标题按来源替换，编号可作为标题内容。
AI 解析（写入契约 JSON 的字段）
relations.enforcementStatus["splitStructure.preview-signature"]
